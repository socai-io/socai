# 小红书评论采集

## 使用与范围

用户要求小红书评论采集时读取本 skill。用户的原始目标、平台、数量、预算和权限优先；这份方法不证明依赖工具、登录、下载、转写、调度或发送能力已经可用。先检查本次工具 schema、真实页面状态和输入身份，再执行。

小红书：保留原作品定位所需参数，使用已暴露的 search/get_notes/author_scan 或站点 manifest 工具，严格以当前 schema 为准。get_notes 已支持的下载、OCR、逐字稿选项按需要开启；用 read_saved_notes 分页读已保存数据，不为取回截断文本反复采集。

## 操作方法

先核对原作品身份、展示评论数及其口径，分开一级评论和回复。使用实际评论采集工具与页面滚动/展开能力，按评论稳定 ID 去重并保留 parent ID；不把已加载首屏当所有一级评论。只展开用户需要的回复，逐轮核对新 ID、滚动位置、加载中、重试/到底提示与剩余范围。到数、到底、限流、登录、超时、无新增各有明确停止原因；展示数可能包含回复、删除或不可见项，无法证明全量时写 partial/不可验证。保留实际已采数据和可恢复位置；恢复同一任务不丢旧评论、不重新计入重复项。分析时声明样本口径，不由热门排序的小样本推断全体比例。

## 交付与完成条件

评论及回复表（作品/评论/父级ID、原文、作者公开标识、时间、点赞、来源）、一级/回复分别计数、覆盖限制与断点。

开始、失败或部分完成都要在当前任务中保留实际步骤和来源。正文、评论、图片、音频、文件或监控的缺失不能用示意数据、推测内容、接口200或构建成功代替。遇到登录、验证码或风控交由用户正常接管，不自动绕过，不重复提交未知结果的写操作。跨任务学习不存放用户资料或平台原文。
