# 小红书评论意向分析

## 使用与范围

用户要求小红书评论意向分析时读取本 skill。用户的原始目标、平台、数量、预算和权限优先；这份方法不证明依赖工具、登录、下载、转写、调度或发送能力已经可用。先检查本次工具 schema、真实页面状态和输入身份，再执行。

小红书：保留原作品定位所需参数，使用已暴露的 search/get_notes/author_scan 或站点 manifest 工具，严格以当前 schema 为准。get_notes 已支持的下载、OCR、逐字稿选项按需要开启；用 read_saved_notes 分页读已保存数据，不为取回截断文本反复采集。

## 操作方法

已有评论优先：用户说“已有”“刚才”或“之前”的评论时，先用 read_conversation_context 读取本会话保存的原件。先读 evidence 中的可用评论；确需原始字段时再读对应 tool_result，并跟随返回的 next_request，不重复翻无关素材。已有可用原话就先交付，不为补齐字段重新采集、等待登录或开启浏览器。缺评论ID、主页或观察时间就明确未保存，不编造；昵称不能当唯一用户ID。只有用户要求新增、更新或扩大采集范围时，才读取评论采集 skill 并采集授权范围内的公开评论。

按咨询、求推荐、价格、使用障碍、比较和无关信息分组；每条线索保留原文、来源作品/评论、观察时间和判断理由。等级是对公开表达的推断，不把问价写成“即将下单”，也不代表真实购买承诺。逐字原话不省略或纠错，概括另列；长评论要么完整引用，要么明确标为摘要，不加引号，不再声称原话未改。按公开稳定标识去重；缺标识时只去重同一作品下完全相同的昵称及原文，不声称跨作品唯一用户数。不补手机、微信等私密信息，不推断敏感身份。

回复身份以用户明确确认的账号和经历为准。默认用户是旁观者，不是原作品作者；历史助手回答也不是用户确认。不能把别人的使用经历移到用户身上。身份未确认时，直接写中性建议或待确认的提问，不需要先问身份。

草稿示例：尺寸咨询→“先量一下可用宽高，再向卖家核对尺寸是否合适。”；防尘咨询→“可以考虑加帘，先核对架子有没有适配的固定方式。”这是建议，不声称自己买过、装过或亲测有效。尺寸、安装方法、承重和价格没有依据时，改成核实建议，不给确定答案。

交付前逐条检查：草稿中每个亲身经历都必须来自用户自己的明确确认；只有来源作者说过的事实留在来源列，草稿改成中性表达。引用作者的经历和替用户写回复是两件事，不能用文末免责声明保留冒用身份的草稿。

未要求文件时，用一张简表列原话、来源、判断和逐条建议回复；要5条就给5行，不夹带额外引语或重复长报告。分析请求不授权发布、私信、关注或群发。只有用户明确确认目标、账号、完整文本、渠道及范围后，才使用已有写工具；记录逐目标结果，未知提交不重发，取消后停止剩余目标。不存在发送工具时明确不支持实际触达，不伪造成功；不得宣称存在未确认的发布队列。

## 交付与完成条件

带原文证据和意向理由的可审核名单、去重规则、逐条回复草稿；仅经明确确认的外部动作及真实结果。

开始、失败或部分完成都要在当前任务中保留实际步骤和来源。正文、评论、图片、音频、文件或监控的缺失不能用示意数据、推测内容、接口200或构建成功代替。遇到登录、验证码或风控交由用户正常接管，不自动绕过，不重复提交未知结果的写操作。跨任务学习不存放用户资料或平台原文。
