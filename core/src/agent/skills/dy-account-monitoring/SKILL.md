# 抖音账号监控

## 使用与范围

用户要求抖音账号监控时读取本 skill。用户的原始目标、平台、数量、预算和权限优先；这份方法不证明依赖工具、登录、下载、转写、调度或发送能力已经可用。先检查本次工具 schema、真实页面状态和输入身份，再执行。

抖音：以当前暴露的 search/get_videos/author_scan 或站点 manifest 工具为准；get_videos 的 download_media、ocr、transcribe_audio 分别代表下载、封面OCR、音频转写，不互相冒充。封面OCR不等于图文作品全部配图OCR；未暴露完整图文提取能力时必须明确缺口。话题/图文支持必须从真实页面与 schema 确认，不能沿用小红书 selector。

## 操作方法

确认账号稳定 ID、监控范围、频率、时区、通知目标和用户授权；建立第一次真实采集基线并保存采集时刻及作品 ID。单次对比只报告新增、可见指标变化及缺失，不把旧作品重新排序当新增；跨样本窗口不能声称账号删除了作品。若当前运行环境暴露真实定时任务能力，创建后必须读回任务 ID、账号/平台、频率、时区、启用状态和下一次运行；未提供定时能力时明确只能本轮对比，不能声称已开启后台监控。沿用已有调度器，不用shell常驻轮询充当监控。只有至少一次后续真实执行产生增量、去重通知被真实接收，并且暂停/恢复状态可读，才能说持续监控验收完成。通知到飞书等外部空间必须确认具体目标和授权，失败保留可重试状态。

## 交付与完成条件

真实基线与增量表、范围和可见性限制；启用时返回可读回的定时任务ID/时区/下次运行及通知状态，缺失能力明确列出。

开始、失败或部分完成都要在当前任务中保留实际步骤和来源。正文、评论、图片、音频、文件或监控的缺失不能用示意数据、推测内容、接口200或构建成功代替。遇到登录、验证码或风控交由用户正常接管，不自动绕过，不重复提交未知结果的写操作。跨任务学习不存放用户资料或平台原文。
