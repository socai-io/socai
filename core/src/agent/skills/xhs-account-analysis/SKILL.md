# 小红书账号分析

## 使用与范围

用户要求小红书账号分析时读取本 skill。用户的原始目标、平台、数量、预算和权限优先；这份方法不证明依赖工具、登录、下载、转写、调度或发送能力已经可用。先检查本次工具 schema、真实页面状态和输入身份，再执行。

小红书：保留原作品定位所需参数，使用已暴露的 search/get_notes/author_scan 或站点 manifest 工具，严格以当前 schema 为准。get_notes 已支持的下载、OCR、逐字稿选项按需要开启；用 read_saved_notes 分页读已保存数据，不为取回截断文本反复采集。

## 操作方法

用户明确“最近N篇”时，把本次`num_notes`设为N，不预防性改成8篇、10篇或整号分层采样。只有实际发现置顶、作品缺失或顺序不可靠时，才说明具体原因并按需补足；新增候选不冒充用户要求分析的样本。未请求评论内容时，互动分析先用已返回的点赞、收藏、评论数，不默认逐篇展开评论；需要评论依据才设置小额评论预算，媒体、OCR和转写也只按本次需要开启。

用主页链接和稳定作者 ID 确认对象，同名不能自动认作同一人。采集简介、可见粉丝与互动字段，以及用户范围内的公开作品；保留置顶、广告、异常和缺失字段标记。按高、中、低互动和主要主题分层取样，说明计划数量、实际数量、时间窗与覆盖限制，不默认所有账号均有50条作品。补代表作品正文、逐字稿、图中文字与评论，分别分析定位/受众、选题地图、标题与开头、信息结构、视觉、语言和互动反馈。每个结论关联具体作品，区分观察、推断和建议。输出可写选题前说明用户业务事实与对标风格的边界。

## 交付与完成条件

先用主页列表确认作者和作品池，再补高、中、低互动代表作。`num_notes`是本次可见列表目标，不是账号总作品数；预览没有读取每篇正文或评论。用户允许不足时，选定相关账号后说明实际数量，不为凑满50篇反复换账号。列表已完整返回时直接分析标题与点赞，不为这些已有字段重复读取大份原始JSON；需要正文、封面或完整字段时才按返回的精确游标读取原件，不猜序号。

交付前将表格、最终答复与来源逐项核对：标为原文的标题、评论须逐字复制，不能凭记忆重写或拼接；概括另标。置顶只认明确的`is_pinned=true`，作者评论不等于置顶。只读了代表作或少量评论，就用“这几篇/抽样中”限定结论，不能写成每篇、全体读者或把提问与高互动的相关性当成因果。没有逐图读取时不推断图内信息；没有计算时不写均值、占比或精确分类数量。生成前核对，再交付一份最终对比表，避免同名多版让用户猜。

每条评论按原件中的所属`note_id`核对后，才写进该作品的结论或选题依据；某篇未加载到评论就如实写未取得，不能借同账号另一篇的评论补上。收藏多于点赞只是一项观察，不能据此断言用户为什么收藏；方法建议与原文证据分开标明。

重做旧报告时，旧表只用于找到对象与线索，不能自动作为本轮事实依据；沿附件的原任务入口读取实际主页、作品与评论原件。账号“获赞与收藏”不是作品点赞总和，不能相减推算遗漏互动；按粉丝数归一化的样本点赞也不是曝光、转化或商业效率。未覆盖的内容只写“所读样本中未见”，不写“该账号没有”。结论旁保留支持它的具体作品链接；未读图片或音轨的视觉、口播判断明确留空待核。

账号身份和样本范围、定位/主题/结构/视觉/语言报告、对照样本链接、可写选题和未验证判断。

开始、失败或部分完成都要在当前任务中保留实际步骤和来源。正文、评论、图片、音频、文件或监控的缺失不能用示意数据、推测内容、接口200或构建成功代替。遇到登录、验证码或风控交由用户正常接管，不自动绕过，不重复提交未知结果的写操作。跨任务学习不存放用户资料或平台原文。
