# 小红书研究报告结构模板

生成研究报告、简报或表格时套用这个结构。删掉与本次任务无关的章节，不要为了凑齐全套而注水。

---

## 封面信息

- 研究问题：一句话说清要回答什么
- 检索式：实际用过的关键词和筛选条件（照实写，含 `--filter` 取值）
- 样本量：搜索得到 N 篇，其中深读 M 篇
- 时间范围：所依据笔记的日期区间（小红书搜索是相关性排序，必须交代）
- 生成时间

## 结论先行

少数几条。**只放你愿意为它背书的话**，每条后面挂上支撑它的笔记链接。

## 线索清单

这一节通常是报告里最长、也最有价值的部分。线索不需要验证，没有出处也可以写——存疑就标一句「待验证」照样放进来。**丢掉一条真线索的代价，远大于保留一条假线索。**

按维度分条，例如：

- **反复出现的词** —— 品类黑话、成分名、被吐槽的点，出现频次本身就是信号
- **异常值** —— 互动量远超同类的笔记，往往踩中了某种真实共鸣
- **评论区捡到的** —— 正文没提、只有评论里才有的反馈
- **还没被搜过的角度** —— 下一轮该试的关键词

每条一行，有链接就附，没有就空着，不要为了补链接去现搜。

## 关键发现

按主题分节，每节：

1. 发现本身
2. 支撑证据（引用笔记正文或评论原文）
3. 来源链接（**原样复制 `url`，含 `xsec_token`**）

引用格式：

> 「评论原文或正文摘录」—— @作者名，《笔记标题》，2026-9-27，赞 1.2万
> https://www.xiaohongshu.com/explore/<id>?xsec_token=...

## 数据概览

适合放表格。注意互动数是字符串，做排序或计算前先换算（万 = ×10000）：

| 笔记 | 作者 | 日期 | 点赞 | 收藏 | 评论 | 链接 |
|---|---|---|---|---|---|---|
| | | | | | | |

## 评论区声音

正文可能是商单，评论区的追问和吐槽更接近真实诉求。

- 高频问题
- 典型吐槽 / 顾虑
- 被追问最多的点（这通常是内容或产品的缺口）

## 账号观察

（涉及品牌、门店、机构时的可选项）

- 官方账号：是否已认证、认证类型、粉丝量级、更新频率
- 半官方与矩阵号
- 普通用户讨论占比

## 局限与缺口

如实写，这一节决定报告的可信度：

- 样本只覆盖了哪些关键词，没覆盖哪些
- 是否遇到限流、登录失效、内容不可见
- 官方信息是否经过主页核实
- 最新相关笔记的日期，以及结论可能过时的程度

## 还没验证的猜想

明确的推测，标注为猜想而不是结论。用户拿报告是去做判断的，这些往往比结论更有启发性——**但必须清楚标注，不要把猜想包装成结论。**

## 下一步建议

基于证据的可执行动作，不要给无法落地的空话。

如果想不出可执行动作，至少给「下一轮该搜什么」——让读者知道这不是终点。

---

## 写作约束

- **结论**必须能追到具体笔记，不写无源的概括；**线索和猜想**不受此限，单独成节并标注即可。
- 宁可多给线索、少给结论，也不要反过来。报告的价值在于打开可能性，不在于显得滴水不漏。
- 链接一律用返回的 `url`，不自己拼 `note_id`。
- 数字保留原文（如 `1.2万`）或换算后注明，不混用。
- 区分「笔记正文说的」「评论说的」「博主资料写的」三种来源。
- 用用户提问的语言写。
