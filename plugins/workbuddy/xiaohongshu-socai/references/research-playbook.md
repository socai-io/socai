# 小红书研究打法

## 一条铁律：搜索排序是相关性，不是时间

小红书搜索结果按相关性排，一页里常混着几个月甚至几年前的笔记。

- 引用任何笔记前先看 `date` 字段，别把旧帖当现状。
- 不要为了"让结果更新"就加 `publish_time` 筛选——那会破坏小红书最擅长相关性排序，反而拿到更差的样本。
- 正确做法是照常搜，然后逐条核日期，必要时说明"最新相关笔记是 X 月的，可能已过时"。

## 官方账号跳转规则

当问题涉及**由主体自己宣布或决定的事情**——营业时间、价格、活动、规则、开闭店、课程安排——并且结果里出现了看起来像该主体官方账号的博主时：

**不要只凭搜索样本下结论。** 用 `socai xhs author <author_id>` 进主页再确认一次。理由：

1. 主页作品按时间倒序（置顶笔记可能排在顶部），能看到搜索排序漏掉的最新公告；
2. 主页头部有 `verified` / `verification`（企业认证 / 个人认证），能确认官方身份；
3. 主页默认只读第一屏网格，最新那条可能不在里面——传 `--num-notes` 抬高。

判断顺序：搜索样本里官方公告的日期已经足够新 → 直接作答，不用跳；样本里官方信息过期、互相矛盾、或压根没出现 → 必须跳主页。

如果根本没找到官方账号，就用默认排序的样本作答，如实写出所依据笔记的日期。

## 区分账号类型

读任何结果集时，给每个作者归类：

- 主体自己的官方号（品牌 / 门店 / 场馆 / 主办方）
- 半官方声音（员工、教练、店长）
- 聚合搬运号、种草矩阵号
- 普通用户

涉及体验、观点、推荐这类**没有权威主体**的问题时，普通用户笔记就是证据，不需要跳主页。

## 常见场景配方

### 竞品 / 品类调研

1. `search "<品类词>" --num-notes 15 --num-comments 8` 拿大盘；
2. 用 `--preview --num-notes 30` 先扫标题定重点，再对重点笔记 `get-notes` 深读；
3. 对出现频次高的品牌账号各跑一次 `author`，看它们自己怎么讲卖点；
4. 评论区是真实的购买顾虑来源，这场景把 `--num-comments` 提到 12 左右。

### 口碑 / 舆情

1. `search "<品牌名>"` 与 `search "<品牌名> 避雷"` / `"<品牌名> 翻车"` 各跑一次，正反都要；
2. 重点读评论而非正文——正文可能是商单，评论里的追问和吐槽更真；
3. 笔记带图且关键信息在图里（价目表、菜单、包装）时加 `--ocr`。

### 达人筛选

1. `search "<领域关键词>" --num-notes 20 --preview` 找出高频作者；
2. 对每个候选 `author <id> --num-notes 20 --preview`：看粉丝量级、认证、作品更新频率；
3. 再看单篇互动（点赞/收藏）判断真实影响力，粉丝数高但篇篇个位数互动是水号；
4. 需要判断是不是软广矩阵号时，读它几篇正文的文风一致性。

### 选题 / 内容创作

1. `search "<选题方向>" --num-notes 20 --preview` 看什么标题在跑；
2. 对高互动的 5-8 篇用 `get-notes --num-comments 12` 深读，重点看评论区在追问什么——那是选题缺口；
3. 图多的笔记加 `--ocr`，小红书很多干货写在图里；
4. 输出时给出标题模式、封面类型、正文结构、评论区高频问题的归纳。

## 深度控制建议

| 需求 | 建议参数 |
|---|---|
| 快速探一眼 | `--preview --num-notes 20` |
| 标准调研 | `--num-notes 10 --num-comments 8` |
| 重评论讨论 | `--num-comments 12`（超过 12 会明显变慢） |
| 需要图里文字 | 加 `--ocr` |
| 需要视频内容 | 加 `--transcribe-audio` |
| 需要本地素材 | 加 `--download-media` |

`--num-comments` 超过 12 会引入额外的滚动和展开回复轮次，延迟显著上升。默认 8 通常够用。

## 历史缓存

结果里出现 `already_analyzed`、`history`、`history_level`、`history_include_media`、
`skipped` 等标记，说明 socai 对这篇笔记有**跨运行的历史缓存证据**。

把它当已有证据用，不要以为笔记被跳过了。只有当缓存的深度（评论数、是否含媒体）不够当前任务用时，才用更深的参数重跑。

**实测行为**：历史缓存会把上一次运行的 `ocr_text` 一起合并回来。也就是说，同一台机器上先前跑过带 `--ocr` 的同关键词检索，之后不带 `--ocr` 重跑也可能直接得到图文 OCR 结果。这不是异常，不用觉得参数没生效——但也不要因此假定 OCR 一定会回来，新笔记首次读取仍需显式加 `--ocr`。

## 不要做的事

- 不重试同一条命令硬碰风控——换路径或如实说明。
- 不把 `note_id` 拼成 URL——必须用返回的 `url`，否则桌面端打不开。
- 不把 `999+` / `收藏` 这类字符串当数字比大小。
- 不在 `reason:"login_required"` 时空转重试。
- 不为了"凑够 num_notes"去跑明显无关的关键词。
